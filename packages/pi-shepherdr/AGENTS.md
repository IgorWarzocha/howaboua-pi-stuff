- Herdr owns layout, process lifecycle, and Pi session restoration. Compose its workspace, tab, pane, agent, prompt, and event primitives; do not add managed layouts, resume, focus, release, or close policy. A failed atomic `spawn` may roll back only the tab/workspace it just created.
- Monitoring owners: `MonitorState` holds terminal-keyed persisted activity variants; `MonitorEvents` owns subscription handover/reconnect; `SettlementReporter` collects and delivers results or resolves one claimed attempt; `AgentMonitor` only composes them. Keep monitoring event-driven with snapshot reconciliation—never poll worker progress or truncate tasks/responses. Session readers scan backward from EOF along the active `parentId` chain; never load a whole transcript. Unclaimed finished, failed, and blocked reports use `steer`, with `triggerTurn` only for idle controllers; never use `followUp`.
- Herdr 0.9 owns the machine catalog and interactive setup; route by opaque profile ID, never labels or UI selection. Read the controller host's catalog through its inherited `HERDR_BIN_PATH`. Do not restore separate Shepherdr machine configuration.
- `AgentFleet` owns machine-qualified identity, aggregate persistence and connection state. Remote SSH attempts happen on activation, catalog refresh or explicit `/herdr connect`, never on a retry timer; `RemoteHerdrClient` alone deploys and runs the remote `~/.pi/agent/shepherdr.mjs` transport and session reader. Bump host/helper `BRIDGE_VERSION` together when their protocol changes.
- Keep `agents` available in every session, including Code and Notebook Mode; start fleet monitoring at session startup. Bare `/herdr` changes only orchestration guidance, restored from session messages, never the working directory. Schemas, orchestration messages, acknowledgements, and injected event content are model-facing contracts; keep them compact and avoid repeated state or identifiers.
- `messages.ts` owns model payloads and rendering details. Preserve task attribution, full responses, actionable blocked CLI commands, and safe restoration of malformed historical details.
- Idle task input must retain Pi's full user kickoff. Promote attributed coordination to developer steering only inside an already prepared run; session readers must recognize that custom message as task input.
