- Herdr owns layout, process lifecycle, and Pi session restoration. Compose its primitives; do not add managed layouts or automatic lifecycle policy. Explicit peer `/quit` closes its pane only after Pi exits; `session_shutdown` is not process exit. A failed atomic `spawn` may roll back only the tab/workspace it just created.
- Monitoring owners: `MonitorState` holds terminal-keyed persisted activity variants; `MonitorEvents` owns subscription handover/reconnect; `SettlementReporter` collects and delivers results or resolves one claimed attempt; `AgentMonitor` only composes them. Keep monitoring event-driven with snapshot reconciliation—never poll worker progress or truncate tasks/responses. Session readers scan backward from EOF along the active `parentId` chain; never load a whole transcript. Unclaimed reports steer active controllers. Idle delivery uses Conversion's durable `nextTurn` staging before a coalesced prepared user kickoff; without Conversion, persist before kickoff. Never use `followUp`.
- Consume Herdr 0.9's machine catalog through the controller host's inherited `HERDR_BIN_PATH`; route by opaque profile ID, never labels or UI selection. SSH setup delegates to Herdr's interactive `machine add`, preserving its approvals and OpenSSH credential ownership. Never write a parallel catalog or edit Herdr's config directly.
- `AgentFleet` owns machine-qualified identity, aggregate persistence and connection state. Remote SSH attempts happen on activation, catalog refresh or explicit panel reconnect, never on a retry timer; `RemoteHerdrClient` alone deploys and runs the remote `~/.pi/agent/shepherdr.mjs` transport and session reader. Bump host/helper `BRIDGE_VERSION` together when their protocol changes.
- Keep `agents` available in every session, including Code and Notebook Mode; start fleet monitoring at session startup. `/herdr` is the only command entry; peer lifecycle dispatch must use its live command context, never a captured context. The human panel owns preferences and machine setup/troubleshooting; agent discovery, attachment, detachment and membership management belong exclusively to agent tools. Explicit orchestration changes affect guidance only and restore from session messages. Refresh UI through owner events, not polling. Schemas, orchestration messages, acknowledgements, and injected event content are model-facing contracts; keep them compact and avoid repeated state or identifiers.
- `messages.ts` owns agent model payloads and rendering details. `pi-agent-board` owns board storage, tools, activity and notices; `board/host.ts` and `board/membership.ts` supply fleet routing and adoption. Preserve task attribution, full responses, actionable blocked CLI commands, and safe restoration of malformed historical details.
- `pi-agent-board` owns the shared durable context-briefing projection. A boundary marker does not prove earlier guidance was retired; use the selected context and preserve immutable briefing IDs through replay.
- Idle task input must retain Pi's full user kickoff. Promote attributed coordination to developer steering only inside an already prepared run; session readers must recognize that custom message as task input.
- `send` never creates task watches or waits for an agent response. `assign` delegates to an existing agent. Delegation settlement promotes its provisional task watch to persistent; completion clears work, not supervision. Rejected submissions still remove newly added provisional watches. Saved records require scope provenance; never revive legacy implicit subscriptions.
- Conversion owns context identity; `shared-context.ts` owns family routing. Fresh spawns bind through the live owner before first task delivery; existing agents attach through aliases without rebinding. Never create or append another process's JSONL. Missing optional API exports disable sharing, not Shepherdr.
- Focus arrivals are passive durable context briefings, not peer tasks. Resolve return arguments in the destination's connected machine namespace and verify host/session, pane, terminal and saved-session identity before focus. Duplex admission must precede outbound frames; buffer early input and replay close to late listeners.
