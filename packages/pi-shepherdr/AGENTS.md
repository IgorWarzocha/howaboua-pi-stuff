- Herdr owns layout, process lifecycle, and Pi session restoration. Compose its workspace, tab, pane, agent, prompt, and event primitives; do not add managed layouts, resume, focus, release, or close policy. A failed atomic `spawn` may roll back only the tab/workspace it just created.
- Monitoring owners: `MonitorState` holds terminal-keyed persisted activity variants; `MonitorEvents` owns subscription handover/reconnect; `SettlementReporter` collects and delivers results or resolves one claimed attempt; `AgentMonitor` only composes them. Keep monitoring event-driven with snapshot reconciliation—never poll worker progress or truncate tasks/responses. Session readers scan backward from EOF along the active `parentId` chain; never load a whole transcript. Unclaimed reports steer active controllers. Idle delivery uses Conversion's durable `nextTurn` staging before a coalesced prepared user kickoff; without Conversion, persist before kickoff. Never use `followUp`.
- Consume Herdr 0.9's machine catalog through the controller host's inherited `HERDR_BIN_PATH`; route by opaque profile ID, never labels or UI selection. SSH setup delegates to Herdr's interactive `machine add`, preserving its approvals and OpenSSH credential ownership. Never write a parallel catalog or edit Herdr's config directly.
- `AgentFleet` owns machine-qualified identity, aggregate persistence and connection state. Remote SSH attempts happen on activation, catalog refresh or explicit panel reconnect, never on a retry timer; `RemoteHerdrClient` alone deploys and runs the remote `~/.pi/agent/shepherdr.mjs` transport and session reader. Bump host/helper `BRIDGE_VERSION` together when their protocol changes.
- Keep `agents` available in every session, including Code and Notebook Mode; start fleet monitoring at session startup. `/herdr` is the only command entry: open the panel or report status without mutation. The human panel owns preferences and machine setup/troubleshooting; agent discovery, attachment, detachment and membership management belong exclusively to agent tools. Explicit orchestration changes affect guidance only and restore from session messages. Refresh UI through owner events, not polling. Schemas, orchestration messages, acknowledgements, and injected event content are model-facing contracts; keep them compact and avoid repeated state or identifiers.
- `messages.ts` owns model payloads and rendering details. Preserve task attribution, full responses, actionable blocked CLI commands, and safe restoration of malformed historical details.
- Idle task input must retain Pi's full user kickoff. Promote attributed coordination to developer steering only inside an already prepared run; session readers must recognize that custom message as task input.
- `send` is message-only: no wait, watch or task mutation. `assign` delegates to an existing agent. Automatic watches are task-scoped and survive blockage, not completion; only explicit `watch` is persistent. Saved records require scope provenance; never revive legacy implicit subscriptions.
- Conversion owns context identity; `shared-context.ts` owns family routing. Fresh spawns bind through the live owner before first task delivery; existing agents attach through aliases without rebinding. Never create or append another process's JSONL. Missing optional API exports disable sharing, not Shepherdr.
