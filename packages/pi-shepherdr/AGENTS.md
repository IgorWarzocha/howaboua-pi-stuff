- Herdr owns layout, process lifecycle, and Pi session restoration. Compose its workspace, tab, pane, agent, prompt, and event primitives; do not add managed layouts, resume, focus, release, or close policy. A failed atomic `start` may roll back only the tab/workspace it just created.
- Monitoring owners: `MonitorState` holds terminal-keyed persisted activity variants; `MonitorEvents` owns subscription handover/reconnect; `SettlementReporter` collects and delivers results; `AgentMonitor` only composes them. Keep monitoring event-driven with snapshot reconciliation—never poll worker progress or truncate tasks/responses. Session readers scan backward from EOF along the active `parentId` chain; never load a whole transcript. Every finished, failed, or blocked report uses `steer`, with `triggerTurn` only for idle masters; never use `followUp`.
- `AgentFleet` owns machine-qualified identity, aggregate persistence and connection state. Remote SSH attempts happen once on activation or explicit `/herdr connect`, never on a retry timer; `RemoteHerdrClient` alone deploys and runs the single remote `~/.pi/agent/shepherdr.mjs` transport and remote session reader. Bump host/helper `BRIDGE_VERSION` together when their protocol changes.
- Keep `herdr_agents` inactive outside explicit master mode. Its schema, orchestration guideline, acknowledgements, and injected event content are model-facing contracts; keep them compact and avoid repeated state or identifiers. Remeasure the README token claim after schema, description, or guideline changes.
- `messages.ts` owns model payloads and rendering details. Preserve task attribution, full responses, actionable blocked CLI commands, and safe restoration of malformed historical details.
