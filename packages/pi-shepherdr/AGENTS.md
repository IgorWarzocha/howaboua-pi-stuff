- Herdr owns layout, process lifecycle, and Pi session restoration. Compose its workspace, tab, pane, agent, prompt, and event primitives; do not add managed layouts, resume, focus, release, or close policy. A failed atomic `spawn` may roll back only the tab/workspace it just created.
- Monitoring owners: `MonitorState` holds terminal-keyed persisted activity variants; `MonitorEvents` owns subscription handover/reconnect; `SettlementReporter` collects and delivers results or resolves one claimed attempt; `AgentMonitor` only composes them. Keep monitoring event-driven with snapshot reconciliation—never poll worker progress or truncate tasks/responses. Session readers scan backward from EOF along the active `parentId` chain; never load a whole transcript. Unclaimed finished, failed, and blocked reports use `steer`, with `triggerTurn` only for idle controllers; never use `followUp`.
- `AgentFleet` owns machine-qualified identity, aggregate persistence and connection state. Remote SSH attempts happen once on activation or explicit `/herdr connect`, never on a retry timer; `RemoteHerdrClient` alone deploys and runs the single remote `~/.pi/agent/shepherdr.mjs` transport and remote session reader. Bump host/helper `BRIDGE_VERSION` together when their protocol changes.
- Keep the selected agent tool inactive until bare `/herdr` activates its controller session. Restore that activation only from the session's orchestration-state messages, never from the working directory. The original extension names the tool `herdr_agents`; Shepherdr 2 names it `agents` and projects the same definition into Code Mode. Schemas, orchestration messages, acknowledgements, and injected event content are model-facing contracts; keep them compact and avoid repeated state or identifiers.
- `messages.ts` owns model payloads and rendering details. Preserve task attribution, full responses, actionable blocked CLI commands, and safe restoration of malformed historical details.
