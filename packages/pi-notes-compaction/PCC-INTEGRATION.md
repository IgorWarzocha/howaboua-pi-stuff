# Optional PCC integration

Notes owns its four tools, local storage, family sharing, checkpoint policy and context windows. PCC is optional. Without Notes, PCC provides ordinary Pi and native provider compaction without notes tools.

Notes uses PCC's public `code-mode`, `prompt-mode` and `developer-messages` exports. Code and Notebook defer notes/history discovery. `new_context` remains a sequential model-only tool, never a nested call. Freshness uses persisted Notes receipts and completed tool outcomes, including generic nested-call evidence through exec and wait.

Returned kickoff messages are annotated for developer-role delivery, not sent during preparation. Other models retain ordinary Pi custom messages. Context projection remains active for saved retirement boundaries even when Notes is disabled for the selected model.

Notes owns automatic read-only hybrid note retrieval and its response cache. History reads Pi JSONL sessions, without backend lookup or protected delivery. PCC supplies provider authentication and generic protected-output delivery for encrypted notes. `canDeliverProtectedOutput(pi, ctx)` checks the active delivery capability, not merely whether the PCC package is installed. JavaScript receives ordinary values for plaintext results and receipts for encrypted notes while compatible provider requests receive the original encrypted blocks. Neither package decrypts them locally. Cached data retains account and backend provenance.

The optional `pi-notes-compaction:owner:v1` discovery channel exposes Notes identity, sharing and projection to consumers such as Suggestions. It does not transfer tool registration or session authority. PCC may check this channel for Notes availability during upgrade admission. Normal turn context delivery uses ordinary Pi context hooks. Notes registers read-only branch projection through PCC's public `compaction` export for isolated consumers such as voice summarisation.

Pi owns session lifecycle. Notes decides when to request or cancel compaction. PCC implements the selected provider compaction method and respects context changes from extensions. Neither extension replaces another extension's preparation.
